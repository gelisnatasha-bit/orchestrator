# Как менять чек-лист

Язык книги — русский. Формулировка проверки говорит, что именно должно быть видно. Precondition фиксирует состояние до действия: тип абонента, статус, баланс, какие услуги активны. Event — одно действие. Expected result — один наблюдаемый исход.

## Ответить, где проверяется требование

1. На листе «Чек-лист» отфильтровать «ID требования» или найти текст.
2. Назвать № строки, код связки и роль: главный или попутно.
3. На листе «Кейсы» найти тот же номер в колонке «№ проверки» и назвать код кейса и номер шага.
4. Если требование закрывается несколькими строками, перечислить каждую. Не склеивать их в один ответ с одним Result.

Пример. Флаг `Bundle_Flag_Autopayment` по `APD_GR02` — проверка № 10, главный шаг связки `С-01`.

## Разбить составную строку

Строка составная, если в ней два действия, два статуса, два баланса, два канала или два места, куда смотреть, и для каждого нужен свой скрин.

Резать обязательно:

- статусы получателя `ACT/STD`, `ACT/BAR`, `ACT/SAVE`, `ACT/SUSPQ` — по строке на статус;
- баланс `Line_main` 0 ₽ и остаток, например 0,50 ₽ — две строки;
- ручное и автоматическое отключение;
- USSD на русском и USSD на английском;
- приложение Life и API биллинга;
- история донора и история получателя.

Новые строки получают следующие свободные номера. У каждой своя связка и роль. На листе «Кейсы» у каждой появляется свой шаг со своим Result и номером проверки. В «Попутные №» на листе «Связки» дописывается новый номер, если шаг смотрится в том же прогоне.

Пустая связка остаётся пустой, когда прогон нельзя совместить: другой статус, другой баланс или другая дата.

## Добавить требование

1. Прочитать формулировку и скилл `autopayment-domain`, чтобы не завести услугу получателя туда, где нужен флаг.
2. Добавить атомарные строки на лист «Чек-лист». Result оставить пустым, выпадающий список продлить на новые строки.
3. Подобрать существующую связку. Новый прогон заводить, только если действие и состояние нельзя снять заодно с уже существующим. Тогда взять следующий код `С-xx`, добавить строку на лист «Связки» и кейс на лист «Кейсы».
4. Для существующей связки добавить шаги в её блок на листе «Кейсы». Ячейку «Кейс» расширить объединением на новые шаги. В шаге заполнить действие, куда смотреть, что проверить, ожидаемый результат. Result пустой. В «№ проверки» поставить номер новой строки.
5. Проверить, что сводка считает новые строки.

Модуль Services interaction уже разложен на связки `С-03`, `С-12`, `С-13` и `С-19`. Повторно не дублировать, если новая фраза покрыта этими прогонами. Новое отличие выносить отдельной строкой.

## Компактная высота строк

Фиксированная высота на все строки оставляет пустое поле в коротких ячейках и прячет текст в длинных. Высоту считать по самой длинной ячейке строки.

Ориентир для Calibri 10: в строку помещается примерно столько знаков, какова ширина столбца. Число строк текста умножить на 13 пунктов и прибавить 3. Нижняя граница около 16–18 пунктов. Колонку «Кейс» на листе «Кейсы» в расчёт не брать: она объединена по вертикали, высоту задают шаги.

Заголовок листа и строка шапки остаются низкими, около 18–22 пунктов. После правки короткая строка визуально занимает одну-две строки текста, длинное предусловие выше соседних.
