# Комментарии и документация кода

Это правило действует во всех проектах аккаунта [gelisnatasha-bit](https://github.com/gelisnatasha-bit).

## Что делать

Весь код, который пишешь или меняешь, должен быть **хорошо прокомментирован** и **задокументирован**. Человек должен понять файл, не догадываясь «что автор имел в виду».

Комментарий — короткая подсказка прямо в коде.  
Документация — описание «что это и зачем» у функции, класса, модуля или в README.

## Как комментировать

- Пиши комментарии **на языке пользователя** (обычно русский).
- Объясняй **зачем** этот кусок нужен и **что он делает**, а не повторяй очевидное слово в слово.
- Не оставляй нетривиальную логику без комментария: условия, циклы, формулы, обходы ошибок, «магические» числа.
- Если строка неочевидна через месяц — рядом должен быть комментарий.
- Не комментируй только то, что и так видно из названия (`i = i + 1` без пояснения, зачем сдвиг). Если зачем неочевидно — поясни.

## Как документировать

- У каждой публичной функции, класса, модуля — описание: что делает, какие входящие данные, что возвращает, какие побочные эффекты (например, пишет в файл или в базу).
- Используй принятый в языке формат: docstring в Python, JSDoc в JavaScript/TypeScript, аналог в других языках.
- Новый проект, пакет или важный модуль — коротко опиши в README: зачем он, как запустить, где главное.
- Если меняешь поведение — обнови комментарии и документацию в том же изменении. Не оставляй устаревший текст.

## Пример

Плохо:

```python
def calc(a, b):
    return a * 1.2 + b
```

Хорошо:

```python
def calc(price, delivery):
    """
    Считает итоговую сумму заказа.

    price — цена товаров.
    delivery — стоимость доставки.
    Возвращает сумму с наценкой 20% на товары плюс доставка.
    """
    # 1.2 — наценка 20% (комиссия магазина), не налог.
    return price * 1.2 + delivery
```
