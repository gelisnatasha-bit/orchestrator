# Gitflow без pull request

Это правило действует во всех проектах аккаунта [gelisnatasha-bit](https://github.com/gelisnatasha-bit).

## Зачем так

Обычный GitHub-поток с pull request здесь **не используем**. Каждая фича живёт в своей ветке и в своей папке (worktree), чтобы несколько задач можно было вести параллельно и не смешивать файлы.

**Ветка** — это линия коммитов с именем, например `feat/login`.  
**Worktree** — вторая рабочая папка того же репозитория, уже переключённая на эту ветку. Основная папка проекта при этом остаётся на `master`.

## Основная ветка

Основная ветка называется **`master`** (то, что в разговоре «мастер»).

- Новые репозитории создаём сразу с `master`.
- Если в репозитории пока есть только `main`, а `master` нет — считай `main` основной и мержи в неё.

В `master` **не пишем фичи напрямую**. Туда попадают изменения только слиянием, когда пользователь говорит **Готово**.

## Как начать фичу

1. Короткое имя латиницей: `feat/краткое-имя` (например `feat/login`).
2. Обнови `master` в основной папке проекта.
3. Создай ветку **и** worktree рядом с репо:

   `G:\Projects\personal\<репо>.worktrees\<краткое-имя>`

   Команда: `git worktree add -b feat/краткое-имя "<путь-к-worktree>" master`
4. Сразу переведи агента в эту папку (`move_agent_to_root`) и зафиксируй ветку (`SetActiveBranch`).
5. Коммиты — по просьбе пользователя или когда без коммита нельзя безопасно идти дальше. Не пушь с `--force`. Не создавай PR.

## Алиас «Готово»

Когда пользователь пишет **Готово** или вызывает `/Готово` — это команда «финиш»: закоммитить остаток (если есть), влить ветку в `master`, отправить `master` на GitHub, убрать worktree.

Не открывай pull request. Не вызывай `gh pr create`.

### Шаги «Готово»

1. В папке фичи: если есть незакоммиченные правки — закоммить их (осмысленное сообщение, без секретов в коммите).
2. Проверь, что рабочее дерево чистое.
3. В **основной** папке репозитория (та, что на `master`):
   - `git checkout master` (или `main`, если это основная)
   - `git pull`
   - `git merge --no-ff feat/…` — обычный merge с отдельным merge-коммитом, как в классическом gitflow
   - `git push origin master` (или `main`)
4. Удали worktree: `git worktree remove "<путь>"`.
5. Удали локальную ветку фичи: `git branch -d feat/…`.
6. Переведи агента обратно в основную папку на `master`.

Если Git сообщил о конфликте — остановись, объясни простыми словами, в каких файлах столкнулись правки, и жди решения. Не делай force-push и не переписывай историю.

## Чего не делать

- Не работать над фичей прямо в папке `master`.
- Не делать pull request.
- Не сливать в `master` без команды «Готово» (кроме случая, когда пользователь явно сказал «влить / замержить»).
- Не `git push --force`, не `reset --hard`, не удалять чужие коммиты.
